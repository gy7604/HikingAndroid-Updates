# 산길 워치 전용 승인 게시기 검토본

휴대폰의 `latest.json`·기존 게시 코드는 유지하고, 이미 서명된 워치 ZIP만 별도 승인으로 공개하는 준비본이다. 이 PR은 실제 게시 승인이나 활성화 승인이 아니다. 기본 브랜치 병합·설정 등록·관리서비스 반영·온라인 검사는 각각 승인 범위를 확인한 뒤 진행한다.

- 전용 요청함: [#4](https://github.com/gy7604/HikingAndroid-Updates/issues/4). 현재 실행 댓글 없음.
- 앱 식별자 `sangil-wear`, 모듈 `wear-link`, 기존 패키지 `com.gy7604.hiking.dev`, 원래 인증서를 유지한다.
- 태그 `wear-v<versionName>`, 파일 `HikingWear-<versionName>.apk`만 사용한다. 릴리스 본문의 작은 JSON이 워치 배포 정보이며 휴대폰 feed를 수정하지 않는다.
- 초안 생성·공개 모두 `prerelease: true`, `make_latest: "false"`를 지정한다. 공개 전후 휴대폰 feed blob과 기존 최신 휴대폰 릴리스를 다시 대조한다.
- 휴대폰과 같은 동시 실행 잠금을 사용한다. 다른 워치 공개 상태가 바뀌면 진행하지 않는다.
- 기본 OFF인 `SANGIL_WATCH_PUBLICATION_ENABLED`가 true이고, 소유자가 새 원본 댓글로 정확한 후보·기준을 승인한 첫 실행에만 동작한다. push/PR/schedule 빌드·게시는 없다.
- 기존 APK의 실제 서명·패키지·버전·워치 필수 기능·정확한 시작 화면·32비트 ARM 호환 ABI와 영수증을 대조한다. 앱 실행·빌드·설치·새 키 생성은 하지 않는다.
- 암호화 수신기는 앱/요청함/원본 승인/실행/고정 제어기/기한을 결합한다. 워치를 휴대폰 앱 식별자로 바꿔 전달하지 않는다. 원문 임시 주소는 공개하지 않는다.

## 다음 승인의 형식

다음 내용은 형식 설명이다. 실제 요청이나 현재 버전 게시 승인으로 취급하지 않는다.

```text
/sangil-watch-publish approve <signedRequestId> <fullSourceSha> <versionCode> <apkSha256> <phoneFeedBlobSha> <watchBaselineSha256> <outerZipSha256> sealed-v1

<승인된 버전의 변경 내용>
```

워치 릴리스가 없을 때만 watchBaselineSha256은 64자리 0이다. 이후에는 기존 워치 릴리스의 ID·태그·본문·APK 정보를 정렬해 계산한 SHA-256을 승인한다. 과거 공개본이나 임시 초안이 있으면 임의로 삭제하거나 덮어쓰지 않는다. 현재 공개 휴대폰 버전과 워치 버전은 서로 비교해 다운그레이드 판정을 하지 않으며, 워치 채널 안에서 versionCode가 증가해야 한다.

## 이번에 준비한 결과와 남은 조건

기존 워치 후보 0.1.31-dev/code32, run42457208257, 원래 인증서가 출발점이다. 파일 유효기간·바이트·현재 공개 기준을 실제 요청 직전에 다시 확인해야 하며, 만료를 이유로 자동 재빌드하지 않는다. 이번에는 새 파일 다운로드·기기 조작·공개 요청을 하지 않았다.

현재 관리 MCP 저장9의 도구는 산길 휴대폰·컴프야·HealthBridge만 허용한다. `sangil-wear` 추가 수정안과 합성 전달 시험안은 비공개 공통 검토본에만 준비한다. 관리서비스에 승인 반영하고 실제 합성 전달을 확인하기 전에는 워치 온라인 전달 성공으로 표시하지 않는다. 워치 게시 플래그 등록과 실제 후보 공개는 각각 별도 승인 사항이다.

실패한 게시에는 일부 초안이나 공개 파일이 남을 수 있다. 자동 재시도·덮어쓰기·삭제·과거 버전 강제 설치로 복구하지 않고 실제 릴리스 상태를 읽어 수동 조정 범위부터 검토한다. 이 과정에서도 휴대폰 feed를 덮어쓰지 않는다.

공식 API 기준: [GitHub Releases](https://docs.github.com/en/rest/releases/releases). 사전 릴리스는 최신 정식 릴리스가 될 수 없으며, 코드도 make_latest=false를 명시한다.

## 검증 범위

보호 검사는 가짜 ZIP·가짜 APK 메타데이터·메모리 안의 시험용 암호화 키·가짜 GitHub API로만 실행한다. 실제 Android 빌드, 제품 실행, 클라우드 게시, 서명키 등록, 기기 설치 성공을 의미하지 않는다. 기존 휴대폰 게시기의 원문 파일과 workflow는 변경하지 않는다.
